# nano-web

Static file server that loads a directory into memory at startup and serves each file pre-compressed (brotli, zstd, gzip), with an SPA fallback and a `--dev` reload mode. Published to crates.io as `nano-web`, as binaries on GitHub Releases and as the `ghcr.io/radiosilence/nano-web` image. The hot path is CPU-bound, so the release profile keeps fat LTO and one codegen unit; `bench/` and `techempower/` measure throughput.

## Git

- Work in PRs; never push to main. PRs are squashed; merge main into a branch rather than rebasing.
- Never push tags or run `cargo publish`. CI tags and publishes when a release PR merges.
- Commits are signed.
- Claude Code Review reviews each pull request on open and push; `@claude` in a comment asks it again.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry; to correct a note, edit its fragment. `just changelog --stdout` previews the result. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`), or the Release workflow, branches from main, bumps `Cargo.toml` and `Cargo.lock`, turns the unreleased fragments into the version and opens the release PR. Merging it is the release: CI publishes the crate and the versioned image tags, then creates the GitHub release with the binaries and the changelog section as notes. A push releases only when it changes the version; `gh workflow run ci-cd.yml` on main retries a release that failed part way.
