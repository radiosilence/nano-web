Each change adds one file under `unreleased/<section>/`, named for its pull request (`32-short-slug.md`), holding one `- **Lead.** Detail.` entry; sections are `added`, `security`, `changed`, `removed`, `fixed` and `internal`. CHANGELOG.md is generated from these files by `scripts/changelog.py` (`just changelog`), so it is never edited by hand. A pull request adds its fragment and leaves CHANGELOG.md alone; the release PR (`just release`) runs `--release X.Y.Z`, which turns `unreleased/` into that version and regenerates the file, so two open pull requests never conflict on it. Releases from before fragments were adopted keep their text as each version's `_intro.md`.
